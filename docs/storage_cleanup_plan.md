# 当前目录整理与清理计划

本计划对应用户授权：删除已完成训练的续训状态，清理 CodeBrain，并统一
项目缓存和报告的位置。以下保留审计候选与执行步骤，末节记录本轮实际执行结果。
实际删除、迁移、保留数量和释放空间以
`results/storage_cleanup/cleanup_report.json` 为准。

## 统一目录

| 内容 | 唯一存储位置 | 管理方式 |
|---|---|---|
| 共享 EEG 数据、原始下载、源 NPY | `/data1/llx/<dataset>/` | 各项目复用，保留已有数据版本 |
| 官方预训练权重 | `/data1/llx/pre_weight/` | 配置直接引用，项目不复制 |
| 模型输入、教师目标、历史缓存 | `/data1/llx/BigSmallcollab/cache/` | 包含 `teacher_targets`、`artifacts`；按复用需要保留 |
| 逐折配置、预测、训练权重、执行日志 | `/data1/llx/BigSmallcollab/results/` | 可追溯到数据、配置和 fold/seed |
| 有独立用途的项目权重 | `/data1/llx/BigSmallcollab/weights/` | 不存重复官方预训练 |
| 用户 Excel、CSV、JSON 汇总 | 项目真实 `results/` | 无外部软链接，无 EEG、模型或目标缓存 |
| 历史来源及迁移记录 | 外部 `migrations/`、`git_lfs/` | 本轮保留 Git 历史和 LFS |

代码、正式配置、文档继续存 Git；生成报告默认不提交。外部 `results/`
是逐折训练产物目录，项目 `results/` 是用户报告目录，两者用途明确区分。

## 本轮保留

- 当前新数据源 001、001-4、004、5001 的 585 个 LOSO 基线单元。
- 当前 004、5001 的 1512 个蒸馏单元所需教师、学生最终权重、feature 投影层和目标缓存。
- 正式共享数据集、官方预训练、当前模型输入缓存、逐折指标、预测、配置和来源记录。
- 未完成训练的完整模型、优化器、调度器和 RNG 续训状态。

保留当前教师和目标以支持后续蒸馏；保留学生与投影层以支持续训和特征分析。
删除大续训状态后无法精确恢复已完成实验的旧优化器进度，但仍保留最终模型，
可以按后续方案新开实验。对基线顺序 RNG 的复用由轻量完成记录支持。

## 本轮删除与归档候选

| 候选 | 审计数量／体积 | 删除前要求 |
|---|---:|---|
| 已完成 `training_state.pt` | 351 份／13.58 GiB | 完成记录、结果和相关产物身份通过核对 |
| CodeBrain 最终训练权重 | 380 份／33.91 GiB | 已退休，无运行或后续蒸馏依赖，成绩先归档 |
| 项目 `codebrain.pth` | 按实际文件计 | 无活动配置和进程依赖，保留 CodeBrain 文本记录 |
| 工作树报告目录混入的重复训练元数据、日志 | 按实际审计计 | 外部已有相同实体或先完成迁移，用户报告保留 |

这两组主要候选合计约 47.49 GiB，实际释放量取决于文件是否共享 inode、
是否仍被进程打开，以及最终通过检查的删除清单。CodeBrain 源码保留为历史。

CodeBrain JSON、CSV、配置和训练 history 先归档到：

```text
results/archive/codebrain/codebrain_records.zip
```

同时导出 380 个单元的成绩 CSV。归档只含文本记录，不打包模型、教师目标、
EEG 数据或完整续训状态；实际文件名称与数量记入清理报告。

## 完成状态的轻量迁移

1. 确认 `completed` 标记、最终 epoch、fold/seed 和当前配置一致。
2. 核对结果、数据来源、输入 manifest、预训练以及需保留的模型／预测文件哈希。
3. 保留原状态全部身份字段和终态 RNG，去掉 `model_state`、`optimizer_state`、
   `history`，原子写入 `completed_state.pt`；训练 history 的文本记录仍可归档。
4. 确认轻量记录可读取，再删除已完成的 `training_state.pt`。未完成状态不能转换。
5. 完成结果读取器通过保留指标、配置和来源识别已完成任务；缺少必要身份记录时
   明确报错，不因大断点或退休权重被清理而自动启动重训。

顺序处理 LOSO 折的 001 教师入口需要终态 RNG 以保持后续折顺序；仅保存一个
“完成”标记不能满足这一要求。轻量记录保留原指纹，不重新计算历史实验身份。

## 缓存归位与兼容

当前新数据源模型输入和教师目标缓存保持既有路径及字节不变，避免产生新
fingerprint，也避免重新生成已经可复用的目标。一个教师 fold/seed 的目标
在三个学生和四组蒸馏间复用，不按实验组复制。

旧 `teacher_cache` 和零散历史缓存归入外部 `cache/` 的对应位置。部分历史
代码通过原始 `Path` 读取旧位置，为其保留旧**外部**路径指向新缓存的兼容
软链接，实体只保留一份。项目工作树不建立缓存软链接，不新建 `data_cache`。

用户报告统一使用 `experiments.storage.REPORTS_ROOT` 和
`require_report_output()`；训练产物使用外部存储检查。清理报告目录中的重复
训练元数据和日志，不删除准确率报告及面向用户的 CSV／JSON 汇总。

## 执行顺序与记录

1. 审计目录、重复文件、读取依赖、活动配置和运行进程，生成精确候选清单。
2. 更新完成结果读取和轻量完成记录支持，确保删除不会误触发重训。
3. 归档 CodeBrain 文本记录及成绩，并核对归档数量和哈希。
4. 转换、删除符合条件的已完成续训状态，再删除获准退休的 CodeBrain 权重。
5. 归位历史缓存，清理重复日志和元数据，保留当前新源缓存原路径。
6. 写入 `results/storage_cleanup/cleanup_report.json`，列明删除、迁移、保留、
   兼容路径、异常跳过项，以及清理前后实际占用。
7. 提交并推送本轮代码、正式规则及文档；生成归档和报告默认不进入 Git。

本轮不删除 Git 历史、LFS、共享数据源或当前已计划复用的蒸馏模型与缓存。

## 2026-10-10 执行结果

本轮已执行完成，目录整理后实际释放约 **48.06 GiB**（包含必要的小型归档和
审计记录）。详细操作保存在 `results/storage_cleanup/cleanup_report.json`，
便于查看的摘要位于 `results/storage_cleanup/cleanup_summary.md`。

- 351 份大续训文件共 13.58 GiB 已删除，替换为总计 5.81 MiB 的轻量完成记录。
- 380 份 CodeBrain 实验模型、项目 `codebrain.pth` 和数值缓存已清理；
  4,436 份文本记录归档为 ZIP，380 条训练成绩另存 CSV。
- 历史 Hub、LOSO 教师目标，以及补查的 95 份 fewshot／pilot 目标实体已归入
  外部 `cache/`。旧外部目录／文件别名保留读取兼容；没有复制缓存实体。
- 去掉 16,686 份与外部字节相同的本地训练元数据、过期锁和记录；
  1,907 份日志迁入外部结果目录，重复 QC 记录和无跟踪运行临时文件已清理。
- 12,885 个保护文件的 SHA 全部一致，缺失与内容变化均为 0；585 个基线、
  1,512 个 KD、756 个投影层、126 份当前教师目标完整保留。当前 108 个
  001／001-4 教师完成记录通过来源和产物核对，可正常跳过完成任务。
- 当前准确率 Excel／CSV／JSON 保持原字节。本地 `results/` 从约 807 MiB
  降至约 366 MiB，保留面向用户的报告与文本归档，没有 EEG 或模型缓存。

工作树约 5.8 GiB，其中约 5.45 GiB 为 `.git` 历史对象，本轮保留历史。
这些历史对象与当前使用的模型输入缓存分别管理；不手动删除 Git 对象。
本轮没有启动训练或运行测试。
